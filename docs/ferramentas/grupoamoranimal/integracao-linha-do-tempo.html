3. Passo 1 — Criar endpoint na API

A API precisa de uma nova tabela linha_do_tempo. Schema:

{
  "id": "auto",
  "ref": "DbGwiaUO4n8",           // code do IG ou "ev_123" para eventos
  "tipo": "instagram" | "evento",
  "titulo": "Um dia pode mudar...",
  "descricao": "Legenda completa...",
  "foto_url": "data:image/jpeg;base64,...",
  "data": "2024-03-15",           // YYYY-MM-DD
  "likes": 142,                   // somente IG
  "categoria": "adocao",          // somente IG
  "local": "",                    // somente eventos
  "link": "https://instagram.com/p/...",
  "origem": "instagram" | "api",
  "created_at": "ISO timestamp"
}
Se a API nao suporta criar tabelas manualmente, o endpoint pode ser simulado com um arquivo JSON estatico hospedado no site (veja Alternativa abaixo).

Alternativa: JSON estatico (sem mudancas na API)

4. Passo 2 — Rodar sincLinhaDoTempo.js

# 1. Testar o que seria enviado
node sincLinhaDoTempo.js --dry-run

# 2. Enviar de verdade
API_USER="seu_usuario" API_PASS="sua_senha" node sincLinhaDoTempo.js

# 3. Enviar so 50 posts (teste)
API_USER="user" API_PASS="pass" node sincLinhaDoTempo.js --limite 50

# 4. Reenviar tudo (ignorar dedupe)
API_USER="user" API_PASS="pass" node sincLinhaDoTempo.js --force

O que o script faz:

  1. Le os 360 posts do dataset.json
  2. Converte cada post em formato padrao (ref, tipo, titulo, foto, data, link)
  3. Busca eventos existentes na API
  4. Mescla tudo, ordena por data
  5. Envia novos items para POST /linha_do_tempo
  6. Salva estado em linha_do_tempo_sinc.json (dedupe)
Fotos locais: O script envia fotos de img-resumo-mensal/ em base64. Se nao existir, usa URL do CDN do Instagram.
